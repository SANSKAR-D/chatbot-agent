# Agentic RAG ChatBot - Frontend

## 1. Project Overview (Elevator Pitch)
The frontend of this project is a modern, responsive React application built with Vite. It serves as the primary user interface for an advanced AI chatbot and automated blogging platform. It provides a seamless, real-time streaming chat experience (similar to ChatGPT) and visually renders complex AI responses—including markdown, code blocks, and LaTeX math equations—alongside custom human-in-the-loop interactions.

## 2. Tech Stack & Justification
- **React (v19) & Vite:** Chosen for lightning-fast Hot Module Replacement (HMR) during development and highly optimized production builds. React's component-based architecture perfectly suits the modular UI requirements of a chatbot.
- **TailwindCSS (Implied/Standard):** Used for rapid, utility-first styling to ensure the interface is fully responsive and modern without writing bulky custom CSS files.
- **react-markdown & react-syntax-highlighter:** Essential for correctly rendering the LLM's markdown output, specifically for syntax-highlighting code blocks and rendering structured text.
- **rehype-katex & remark-math:** Used alongside react-markdown to beautifully render complex mathematical formulas and LaTeX equations generated by the AI.
- **html2pdf.js & jszip:** Client-side libraries chosen to allow users to export their generated blogs/documents to PDF and manage downloaded assets directly in the browser, reducing server load.

## 3. Architecture & End-to-End Flow
1. **User Interaction:** The user interacts with the Chat or Blog UI components, typing a query or uploading a PDF document.
2. **Streaming Connection (SSE):** When a message is sent, the frontend opens a Server-Sent Events (SSE) connection to the FastAPI backend (`/chat/stream` or `/blog/stream`).
3. **Real-time Rendering:** As the backend LangGraph processes the query and streams `AIMessageChunk` tokens, the React state is continuously updated. The `react-markdown` component instantly renders the chunks, creating a typewriter effect.
4. **Human-in-the-Loop Interruption:** If the backend graph halts for user confirmation (e.g., a critical tool call like purchasing stock), it yields a `hitl_required` event. The frontend catches this and renders an interactive component (e.g., "Approve" or "Reject" buttons) instead of raw text.
5. **Asset Exporting:** For the blogging workflow, once the markdown is finalized, the user can click a button that triggers `html2pdf.js` to convert the rendered DOM elements into a downloadable PDF report.

## 4. Core Mechanics & Algorithms
### Server-Sent Events (SSE) Parsing & State Management
Handling real-time streams in React requires careful state management to avoid unnecessary re-renders or dropped tokens.
- **The Mechanism:** Instead of a standard `fetch` or WebSocket, the app consumes an EventStream. I use the native `EventSource` API (or a custom fetch reader) to listen to `data:` payloads.
- **State Updates:** As chunks arrive (e.g., `{"chunk": " Hello"}`), the frontend appends the string to the current message's state variable. React's reconciliation engine updates the DOM, and a `useEffect` hook automatically scrolls the chat container to the bottom so the user's view stays locked on the newest text.
- **Markdown Parsing:** Passing a rapidly updating string into `react-markdown` can be computationally expensive. The DOM is updated smoothly by leveraging React's virtual DOM diffing, ensuring only the new text nodes are painted.
